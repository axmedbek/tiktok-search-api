# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added
- **`POST /profile` and `POST /user/posts`** — a user's profile and that user's videos, entered by handle (`@bakuesaz`). Both are validated at the Pydantic boundary (24 chars, `[A-Za-z0-9._]`, one leading `@` stripped; hyphens rejected because TikTok handles have none), both map `NotFound` → **404**, and both share the single `_domain_errors()` map that `/search` was also folded into. `/profile` costs one signed request; `/user/posts` one per page.
- **Interim serving path, and it is machine-readable.** The dedicated upstream endpoints (`/aweme/v1/user/profile/other/`, `/aweme/v1/aweme/post/`) are live but reject this client's param set, so both endpoints are served from a **search** reply instead. `/profile` flattens the `user_list` node the handle resolve already fetched — 101 keys, everything needed except `signature` and `region_code`, which are structurally absent (measured null across 15 users) and documented as always-null. `/user/posts` keyword-searches the handle and filters by author, and carries required `source: "search"` and `complete: false` fields so a caller can detect the interim semantics rather than read a doc footnote. Its ceiling is real and stated: yield depends on how distinctive the handle is as a search term — 48 of 60 raw items for `@bakuesaz`, but 4 of 150 for `@nasa`, whose handle is a global topic.
- **Posts are ordered newest-first** by `create_time`, unknown dates last. The sort key is a string comparison, which is sound because `_iso_utc` always emits a fixed 25-char `YYYY-MM-DDTHH:MM:SS+00:00` (verified over the full `datetime` range including negative epochs), so lexicographic order *is* chronological order. **A sorted page is not a globally sorted stream** — pages still arrive in search-relevance order, so a paginating caller must accumulate and re-sort; `demo.html` does.
- **`PayloadShape`** — emptiness classification is now a **required** per-call argument to `_get_signed`, not a module constant, so a new endpoint cannot inherit the search rule by omission. The search rule (`no item list AND not has_more`) applied to a profile reply calls every *successful* call a shadow-block; applied to a posts reply it 502s a private account whose `aweme_list` is legitimately `[]`.
- **`errors.NotFound`**, deliberately NOT a `SoftError` subclass: `pool.run` penalises the identity only inside `except SoftError`, so staying outside that hierarchy is what makes "a deleted user costs the identity nothing" structural rather than conventional. Raised without consuming retry budget — re-signing cannot make a deleted user exist.
- **`pool.run_call(fn, *, handle=None)`** — the seam every pooled call goes through; `fn` returns `CallOutcome(result, verdict)` with an explicit `HealthVerdict` (`OK`/`EMPTY`/`NEUTRAL`, no default, unrecognised value raises). A posts page that legitimately returns nothing is **NEUTRAL**: three `EMPTY`s retire the only warm identity and 503 every caller, and a run of low-visibility handles is not evidence of risk-control. `run` is now a thin wrapper.
- **Per-path cursor bound** in `paging.py` — search paths keep `MAX_ENDPOINT_CURSOR` (100_000, an offset), the posts path gets `MAX_MS_EPOCH_CURSOR` (2100-01-01Z, a calendar ceiling on a creation time). Fail-closed: an unknown path gets the strict bound. Enforced on **`encode` as well as `decode`**, because a server that mints tokens its next request rejects is worse than one that refuses to mint.
- **`demo.html` gained a `👤 Profil` tab** reusing the existing card renderer, pagination loop and JSON toggle, plus hardened helpers: `esc()` now escapes quotes and coerces non-strings (it previously threw on a number and could not safely fill an attribute), `safeUrl()` gates avatar URLs to http(s), and `detailText()` renders FastAPI's array-shaped 422 `detail` — which used to show `[object Object]` on every tab.
- **`author_unique_id` on `flatten_video`** (raw `unique_id`, no nickname fallback) and `sec_uid` / `author_sec_uid` on the flatteners. Additive only: no existing key changed name, type or presence.

- Claude Code dev-flow infrastructure: `CLAUDE.md`, `agent_docs/` (architecture, testing, agents-config, common-changes recipes), `.claude/agents/` (backend-dev, architect-review, spec-compliance-reviewer, api-verifier, unit-tests, integration-tests, test-case-writer), `.claude/commands/` (start, dev, end, verify, debug, onboard, onboard_setup), `.claude/rules/` (code-standards, security, anti-block, api-service, git-workflow, communication, agent-docs-standards, learned-lessons), and `.claude/workflows/06-task-execution-protocol.md`.
- `IdentityStore` hot-reloadable warm-identity manager with per-identity health tracking (`identity_manager.py`); pool integration; `capture_identity_addon.py` mitmproxy addon for credential refresh.
- Docker deployment: `Dockerfile` (`python:3.11-slim`, non-root, stdlib-urllib healthcheck) and `docker-compose.yml` running the API on `127.0.0.1:8000` plus `mobile/demo.html` via `nginx:alpine` on `127.0.0.1:8080`. Config and warm identities are bind-mounted read-only from `./mobile`; `.dockerignore` keeps every profile and `identities.json*` out of the build context.
- `RAPIDAPI_KEY` environment override for the signer key (`RAPIDAPI_KEY_ENV` in `config.py`), so the key no longer has to live in a committed profile. `.env.example` documents it; `.env` is git-ignored.
- Cross-request pagination via `page_token` (`paging.py`). TikTok's search is a session: a request at `offset > 0` must echo the previous reply's `search_id` (`log_pb.impr_id`) or the API answers `empty_session` and returns nothing — so `next_cursor` was never usable and the demo's "load more" always 502'd. The token is an HMAC-authenticated blob carrying, per endpoint, `(path, cursor, search_id, has_more, started)`, an `hmac`-derived device handle, and a bounded window of recent record-id fingerprints that seeds cross-page dedup. Verified live: three chained pages, 30 distinct ids, zero overlap. `cursor` stays accepted and unchanged for compatibility.
- `PoolCode` on `PoolExhausted`, so `app.py` maps 429-vs-503 on an enum instead of matching the prose substring `'cap reached'`.
- `signer: local | rapid | legacy` (`ClientConfig.resolved_signer()`), and `signer: local` is now the default in `config_direct.yaml`. The vendored pure-Python signer signs v46 **in-process at zero quota**: `MetasecSigner.for_v46()` maps the `sign_*` params onto the four fields `Metasec.sign` actually reads and attaches the warm identity. The long-standing "keys frozen at v37" verdict measured a real failure but named the wrong cause — `signing.py` was passing the v32 `ClientConfig` defaults and attaching no identity. It holds because `mssdk_ver_code 83952160` is shared between the 37.x and 46.x builds. Verified live: page 1 + a `page_token` continuation, 20 + 20 records, zero overlap, and RapidAPI's remaining quota unchanged.
- A WARNING when a `local` identity has no captured `user_agent`: the built UA would quote `version_code=320904` against a v46 signature, which TikTok reads as `hit_shark` — a silent misconfiguration that previously looked like expired credentials.
- Startup misconfiguration banners in `create_app`: `ERROR` when the config path is absent, and when a profile has no usable signer configuration. Originally added because a falsy `rapidapi_key` silently selected the cold legacy signer and disabled hit_shark detection; the `signer:` knob later removed that coupling, so the banner is now scoped to a profile that resolves to the cold `legacy` path, and it names both remedies (`signer: local`, or `signer: rapid` plus `RAPIDAPI_KEY`) because an explicit `signer: legacy` ignores the env key. `create_app` also logs the resolved signer mode at INFO, and validates the mode/key pair **before** the pool is built: `signer: rapid` with no key raises a `ValueError` naming the mode and `RAPIDAPI_KEY` rather than letting `RapidSigner` take startup down from inside pool construction, and no other signer is substituted for it.

### Fixed
- **`/user/posts` could attribute a foreign account's video, and that account's ids, to the requested handle.** The author filter compared `author_username`, which falls back to `nickname` — user-settable and not unique — so anyone could set theirs to a target handle and be returned as it, with `_posts_ids` publishing their `user_id`/`sec_uid`. Nothing errored; the answer was well-formed and wrong. The filter now keys on `author_unique_id`, and a record without one is dropped.
- **A public account could be reported `private: true`.** `private` was coerced with a bare `bool()`, but TikTok's `secret` is a numeric 0/1 flag a reply may render as the string `'0'`, and `bool('0')` is `True` — a silent, inverted, user-visible wrong answer. Numeric flags now go through `mapping._flag`.
- **An out-of-bound upstream `max_cursor` turned a served page into a 500.** `_paginate_posts` did not bound the cursor inbound, so it reached `paging.encode`, raised `ValueError`, and escaped `run_in_executor`. It now retires the endpoint: 200 with the records already served and no continuation. The same `ValueError` net now also covers `/search`, closing its last 500 path.
- **The posts `page_token` was bound to the handle's exact case** — page 1 as `@BakuEsaz` then page 2 as `@bakuesaz` returned 422. The query hash is now computed on the lower-cased handle.
- **`demo.html`'s new error branches leaked onto the three search tabs.** A `/search` stale-token 422 showed a username-charset message, and a wrong `?api=` base rendered "user not found" — naming an identity cause for a wiring problem, on the developer's own diagnostic surface. Both are now gated on the Profil tab.

### Changed
- `client.py` hardened `hit_shark` detection: on a **sessionless first page**, empty `data[]` with `has_more=false` is surfaced as `SoftError` (HTTP 502) instead of a silent empty 200. On a continuation the same shape is the end of the stream — see the `page_token` entries below.
- `api/app.py` `_resolve_identities_path` resolves a relative `identities_path` against the config directory (not process cwd).
- `_direct` is driven by the resolved signer mode instead of `bool(rapidapi_key)`, so a keyless profile keeps hit_shark detection on. `rapidapi_key` is optional; the missing-key startup banner is silent under `signer: local`, where an absent key is normal, and still fires for a keyless profile that derives to the cold `legacy` path.
- `legacy` is structurally identity-free: the identity and v46 headers are gated on the `for_v46` construction rather than on the presence of a cookie, so a profile that carries identities but derives to `legacy` can no longer send a live warm cookie under a v32 signature.
- `from_mapping` rejects an unknown `signer:` value — a `signer: locl` typo would otherwise derive to `rapid` and bill every request.
- **The RapidAPI fallback is deliberately narrow**, and its documented rationale was corrected: it fires only on a hard signer-level `TransportError`, never on an empty/`hit_shark`. An MSSDK bump raises nothing at all — it produces a well-formed signature that risk-control rejects with an empty `200`, so it is indistinguishable from expired credentials. The discriminator is *every* identity failing at once shortly after a TikTok release; confirm by flipping one profile to `signer: rapid` and re-running the same query. That single paid signature is why RapidAPI stays configured.
- `max_results_per_search` raised to 300 (`SearchRequest.limit` `le=300`), and the demo UI's Limit selector now offers 120 / 180 / 200 / 250.
- **A large `limit` no longer returns fewer results.** One request's work budget is now separate from "this endpoint is spent": `_page_budget(limit, page_count)` is `ceil(limit/page_count)` plus `PAGE_BUDGET_SLACK_PAGES`, capped by `MAX_PAGES_PER_ENDPOINT` (12 → 40, now only an absolute backstop), and exhausting it ends the request while leaving the endpoint resumable. The old flat 12-page ceiling retired the endpoint at 120 raw items, so its reasoning ("12 pages without filling `limit` means it is re-serving what the stream already holds") was simply false for any `limit` above 120. Measured on the same keyword within the same hour: `limit=300` returned **34** unique before, **300** after, with the minted `page_token` chaining to 22 further records at zero overlap.

- `next_cursor` is now TikTok's own cursor rather than `start_cursor + len(records)`; the two diverge whenever dedup drops an item. It is informational — callers resume with `page_token`.
- A continuation whose reply is empty is the end of the stream, not risk-control: it returns `200 {count: 0, has_more: false, page_token: null}` in one signed request and is not counted against identity health. Previously every terminal "load more" raised `SoftError`, and three of them retired the sole warm identity and 503'd all callers. The tail is an allow-list (`empty_session`, `federation_empty`, or an empty page with no nil block) that fails closed — `hit_shark` or an unrecognised nil still raises, so a session cannot launder risk-control — and it retires that endpoint regardless of the `has_more` the reply carries.
- The device serving a paginated stream is pinned by a stable `hmac(identity_key)` handle rather than the positional `id{i}` label, which a capture-loop reorder of `identities.json` would repoint at a different device.
- A user search whose page answers `has_more=false` is no longer misread as a shadow-block — `items_any` now covers `user_list`. Pre-existing bug, surfaced because token pagination reaches the final user page routinely.
- `mobile/config_direct.yaml` no longer carries a literal `rapidapi_key` — it now comes from `RAPIDAPI_KEY`. **The previously committed key remains in git history and should be treated as compromised and rotated.**
