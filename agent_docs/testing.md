# Testing

## Framework & layout

- **pytest.** Tests in `mobile/tiktoksearch/tests/`, one file per module under test (`test_<module>.py`).
- Run: `cd mobile && ../.venv/bin/python -m pytest tiktoksearch/tests -q`
- Style: class-based grouping (`class TestSearchFilters:`), plain `assert`, `pytest.raises(ValueError)` for validation failures. No fixtures framework beyond stdlib `tempfile` where a file is needed.

## What to test (pure logic, no network)

The value of this suite is the pure, deterministic logic. Cover:

- **config.py** — `from_mapping` drops unknown keys; `with_overrides` merges non-empty values and tuple-izes `api_hosts`; frozen dataclass immutability.
- **filters.py** — `SearchFilters.to_query_params` emits flat v46 params + legacy blob; `SearchQuery` validation (empty term, negative cursor, filters-on-user rejected); `keyword`/`source_term` derivation.
- **identity_manager.py** — health transitions (N consecutive empty → stale; `report_ok` clears), hot-reload on mtime change, health preserved on same-cred rewrite but reset on new cookie/token, `overrides()` shape, `usable_count`. Use `tempfile` + `os.utime` to drive mtime.
- **pool.py** — slot built per identity, `acquire` skips stale slots, all-stale → `PoolExhausted` with the identity-specific message, daily cap + UTC day roll, `run_merged` dedup. Inject a fake client so no real search happens.
- **mapping.py** — `flatten_video` skips items without `aweme_id`, maps stats/author/music correctly, `to_int` coercion; `flatten_user`; `flatten_profile` (`None` on a `uid`-less payload, `heart_count` from `total_favorited` and never `favoriting_count`); `_flag`'s numeric-first truth table, where `'0'` is `False` and bare `bool('0')` is the inversion that badges a public account private; `_avatar_url`'s largest-first fallback. Lives in `test_mapping.py` — `test_filters.py::TestMapping` is older incidental coverage.
- **client.py pagination/dedup** — `_paginate_into` dedupes by key, stops on `has_more=false` / non-advancing cursor, merges two endpoints. Stub `_get_signed` to return canned pages — never sign or hit the network.
- **capture_diff.py** — the param-diff diagnostic, whose output decides the next task, so the tests are about DIRECTION rather than coverage. `[replayed]` may only ever be UNDER-claimed: a `device_query` key one identity carries and another does not must render `[SUSPECT]` under the no-selector default (an intersection), because `_common_params` replays ONE identity's keys and the pool picks the slot — a union credits identity A with B's key and deletes a real suspect. The exact replay set must EQUAL `frozenset(client._common_params())` for a config carrying that identity's `device_query`; that equality is what every `[replayed]` claim rests on, and it is the only thing holding `_common_params` against drift. A degenerate identity file (absent, `OSError`, bad JSON, non-list, `{"identities": []}`, no `device_query`) yields `None`, never an empty-but-`DEVICE_QUERY_ONE` set — the empty set silences nothing but makes the report claim exactness off a file that supports no claim and stops `main` refusing an explicit flag. Plus: alias masking across every `SENSITIVE_PARAM_NAMES` spelling (`install_id` is `iid`, `android_id` is `openudid`) with no raw value in `as_json_line()` or in `render_report`, `[under-filters]` on the video-search paths only, `resolve_identities_path` precedence, and `load_capture` skipping a bad line by NUMBER with no param content in the log. Never reads `mobile/identities.json` or `mobile/config_direct.yaml`: every config case passes an explicit `--config` under `tmp_path`.

## What NOT to unit-test

- RapidAPI signer HTTP calls, live TikTok search, the capture addon, the emulator loop. These need live identities/proxies/emulator and are verified manually (see `.claude/agents/api-verifier.md` for the curl-based API check).
- Never let a unit test make a real request to TikTok or RapidAPI. Stub at the `_get_signed` / `RapidSigner.sign` boundary.

## Fakes — all in `tests/conftest.py`, do not re-invent them

`conftest.py` is the only stubbing mechanism; adding a parallel one is a review finding.

- **`_forbid_real_network`** (session-wide, autouse) — replaces `HTTPAdapter.send`, so any test reaching a real socket fails loudly instead of spending money or burning an identity. `_assert_no_network_attempted` then attributes a hit to the test that caused it, even if that test swallowed the error.
- **`_stub_signer_and_backoff`** (autouse) — swaps `client.RapidSigner` for `FakeSigner` and nulls the retry `sleep`. Retries are behaviour under test; sleeping for them is not.
- **`transport`** — a `FakeTransport` installed over `requests.Session.get`. Answers from a scripted handler and records every signed GET, so `transport.calls` is the paid-sign ledger: assert on the CALL COUNT, not just the exception, whenever retry budget matters.
- **`rapid_ledger`** — counts paid-signer *constructions*. The narrow local→RapidAPI fallback is a money question, so assert the receipt (0 constructions, or exactly 1), never merely which exception came out.
- **`reply` / `empty_reply` / `videos` / `users`** — canned TikTok replies (`cursor`, `has_more`, `log_pb.impr_id`, `search_nil_info`) driving both the success and the hit_shark branches.
- **`posts_reply` / `awemes`** — the posts endpoint's counterpart to `reply`, differing in the three ways `_paginate_posts` cares about: a bare `aweme_list`, a `max_cursor` walking BACKWARDS, and no search session. `omit_list=True` drops the payload key (risk-control) as distinct from a present-but-empty list.
- **`author_node` / `authored_videos` / `authored_reply`** — a video-search reply with a caller-chosen author PER ITEM. `author_node(nickname=..., unique_id=None)` is the **impersonator** shape: `flatten_video` fills the display field `author_username` from `unique_id or nickname` but the identity field `author_unique_id` from `unique_id` alone, so a nickname-only author must never be attributed to the requested handle (`api/app.py._authored_by`). `authored_reply` takes `(aweme_id, author)` pairs, so one page can carry an impersonator *and* the genuine account — the only shape that separates a right answer from a right-looking one.
- **`DEFAULT_CREATE_TIME` / `create_times=`** — every canned aweme now carries a `create_time`, because every real one does. `videos` / `authored_videos` / `reply` / `authored_reply` / `awemes` / `posts_reply` all take `create_times`, a `str(aweme_id) -> epoch int` mapping: an id absent from it gets `DEFAULT_CREATE_TIME`, and a mapped value of **None drops the key** (the undated record `_newest_first` sorts to the tail — upstream `create_time: 0` arrives as the same None, since `_iso_utc` reads a falsy ts as unknown). The shared default is deliberate: all-equal keys leave a stable sort order-preserving, so stamping it changed no existing expectation. Before it existed the builders omitted `create_time` entirely, so `mapping._iso_utc` returned None for every fake, every `_create_time_key` was the unknown-date sentinel, and `/user/posts`' newest-first sort was a **provable no-op across the whole 497-test suite** — pass a `create_times` mapping in any test that touches ordering, or the assertion is vacuous.
- **`profile_node` / `user_search_reply`** — a user-search `user_info` node and the reply wrapping it, for `/profile` (served from the user-search node, not a profile path). `profile_node` carries NO `signature` and NO `region` on purpose — both are structurally absent upstream, which is why those two fields are interim-null; pass any key as None to drop it (that is how the `uid`-less node that flattens to None is built). An EMPTY `user_search_reply([])` is the sessionless empty item list read as risk-control (502, reported), distinct from a POPULATED list with no exact handle match (404, not reported).
- **`local_config` / `MetasecSpy`** — a warm `signer: local` config from synthetic material, and a spy over the vendored `Metasec` so the v46-vs-v32 param mapping is observable. The local signer's crypto runs for REAL in tests: that is a signature, not a request.
- **`AsgiClient` / `drive`** — a stdlib ASGI driver (no `httpx`, no `TestClient`). It has `post()` only; a GET endpoint needs a `get()` added.
- **`write_identities` / `identity` / `write_config`** — synthetic identity + config temp files with fake ids and a fake cookie. `mobile/identities.json` is NEVER read by a test. `identity(device_id, device_query=...)` replaces the default two-key fingerprint outright, because those KEY NAMES are themselves behaviour: `_common_params` replays exactly one identity's keys, so a HETEROGENEOUS file (entry A carrying a key entry B does not) is the only shape that can tell an intersection apart from a union over entries — which is the whole `[replayed]` direction argument in `test_capture_diff.py`. Default `None` keeps the shape every earlier test was written against.
- **`tests/fixtures/captured_requests_sample.jsonl`** — a committed capture fixture (8 records: both video-search paths, user search, the post grid twice, the profile path, and one path this client does not call). Values are fake and ALREADY masked, as the addon writes them, so it also exercises mask idempotence on the way out. It is committable because `.gitignore`'s `!**/tests/**/*.jsonl` re-includes it under a `tests/` tree — verify with `git add --dry-run` before adding another, since a repo-wide `*.jsonl` rule passes locally off an untracked file and breaks on a fresh clone.

## Proving an assertion bites

A test that passes against a broken implementation is worse than no test. For a change to load-bearing classification logic, mutate the production rule, confirm the new tests fail, then restore it (verify by checksum). `test_wiring_payload_shape.py` was accepted on that basis — five mutations, each caught; `test_wiring_profile_posts_api.py` on 19; `test_wiring_posts_newest_first.py` on 8, every one of which had survived the whole pre-existing 497; `test_mapping.py` and the epic's closing gap-fill on 31, including two that discriminate an end-to-end pin from the pure one it sits beside (a `ValueError` netted in `_domain_errors` leaves `_iso_utc`'s own pin green). `test_capture_diff.py` was accepted on 17, of which 16 were caught and every one had survived the whole pre-existing 676: the two that matter most mutate `client._common_params` itself (a key GAINED and a key DROPPED), because the tool's every `[replayed]` claim is an assertion about that method and nothing else in the suite pins it. The one deliberate survivor is `FILTER_PARAM_NAMES` replaced by a literal equal to today's derived set — that is not drift, and the companion mutation (the same literal with `general_filter_sort_type` missing) is caught, which is exactly the discrimination the derivation exists for.

Four shapes of worthless assertion are on record here, all from real holes:

- **An identity-health assertion that starts from a ZERO counter** cannot tell a reset from a no-op, so it passes for OK *and* for NEUTRAL. Park the consecutive-empty count at `DEFAULT_STALE_AFTER - 1` and add a `_report` spy as a second instrument — that is what "reported neither ok nor empty" actually requires.
- **An ordering assertion over records that all share one sort key**, which is the whole-suite version of the same mistake. `/user/posts`' newest-first sort was untested for a subtask and a half because no fake carried a `create_time`: every key was the unknown-date sentinel, and a stable sort over equal keys is byte-identical to no sort at all. Three mutations passed 497/497 — `reverse=True` deleted (feed served OLDEST-first), the `_newest_first` call removed from the handler, and the sentinel changed from `''` to `'zzzz'` (undated records lifted to index 0, fabricating "this is the most recent post"). Two rules follow: date the fakes (`create_times=`), and **arrange the page so the sort MOVES something** — if the upstream order already equals the sorted order, the assertion is that same no-op. Where a string sort key stands in for a parsed date, pin the width/format premise as a property of the renderer (`mapping._iso_utc` is a fixed 25-char `YYYY-MM-DDTHH:MM:SS+00:00` across the whole `datetime` range, negative epochs included): a `Z` suffix or a float `ts` mis-orders everything silently, and both survived 497/497 too.
- **A bound asserted against its own constant.** `'9' * (MAX_USER_ID_CHARS + 1)` is rejected at *any* ceiling, because the case moves with the constant — the same no-op as `len(encode(worst)) <= cap` passing under any cap. Pin the ceiling as a literal beside the cases (`USER_ID_LIMIT = 32`, asserted equal to the constant), so widening it fails.
- **A "key is present" assertion** on a filtered endpoint. `/user/posts` attributed a foreign account's ids to the requested handle and every key was present and well-typed throughout. Assert on the RESPONSE BODY (the foreign ids absent from the whole of it), from a page that carries the impostor *beside* the genuine record — an impostor-only page answers `count: 0` on an endpoint that returns nothing at all. Where two fields must stay different (`author_username` falls back to `nickname`, `author_unique_id` does not), pin both on ONE record in ONE test, or the pair passes after someone "harmonises" them.
