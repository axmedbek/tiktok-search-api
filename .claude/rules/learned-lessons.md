# Learned Lessons — Mandatory Rules

Rules from real failures on this project. NOT suggestions — requirements.
Format per `.claude/rules/agent-docs-standards.md`: `- **<Symptom>.** <Cause>. **Fix:** <the standing invariant, phrased as something that IS true>`.

## Risk-control / empty results

- **Search returns HTTP 200 with empty `data[]` ("arada boş" / "100/100 empty").** ByteDance `hit_shark` soft-rejects the request on identity distrust — expired warm `cookie`/`x_tt_token`, cold device, or bad IP — not a signing failure. **Fix:** an empty direct-mode result is diagnosed as an identity problem first (health/staleness, sessionid cookie + x_tt_token present, residential proxy assigned) and is surfaced as `SoftError` (HTTP 502), never a silent 200 with empty records.

## Delegation / pipeline

- **A review cycle is spent rejecting a field the implementer was told to add.** The `/dev` delegation prompt restated the plan in its own words and, in doing so, specified a function signature and a response key (`flatten_profile(user, source_term)`) that the approved contract did not list — so `backend-dev` complied with the prompt while diverging from the plan, and both reviewers correctly flagged it. **Fix:** a delegation prompt cites the plan's contract as the authority and never invents a signature, key, or field the plan does not name; where the plan is genuinely silent, the prompt says so and asks the implementer to choose, rather than inventing a value that then reads as approved.

- **A reviewer's prescribed wording is pasted into an implementer's prompt and becomes a false comment in the codebase.** Happened twice in one session: a review's suggested docstring sentence about how `encode` fails, and a review's "this mutation still passes 352/352" claim — both were relayed verbatim into the next delegation, both were measured false by the agent that acted on them. A reviewer reasoning from reading is not the same as a measurement, and a prompt strips the difference: the implementer receives an assertion with no visible provenance and writes it down as fact. **Fix:** a claim about observable behaviour is relayed with its provenance attached ("the reviewer reasoned X — verify it before writing it down"), and any figure or failure mode destined for a comment, a doc or a lesson is measured by whoever writes it. Review findings are hypotheses until executed.

- **A fully green suite certifies logic that is provably broken.** Across one Epic, **nine** mutations to load-bearing rules survived a 497-test green run: `_REPORT_BY_VERDICT[NEUTRAL] = True` (a dying identity could never reach `DEFAULT_STALE_AFTER`, because every session tail cleared its counter), `reverse=True` deleted from the post sort (every feed inverted), `encode`'s cursor bound removed, `_iso_utc` switched to a `Z` suffix. Each was invisible for a specific, repeatable reason: the fixtures never set the field under test, the assertion restated the definition it was checking, or the pre-state already equalled the post-state so the operation had nothing to do. **Fix:** a test over classification, ordering or health-verdict logic is accepted only with a mutation table — mutate the production rule, confirm the test fails, restore, verify by checksum. Four assertion shapes are recorded in `agent_docs/testing.md` as looking sound and proving nothing: a health counter starting at zero (a reset and a no-op are indistinguishable there), `isinstance(x, str)` on a formatted timestamp, `len(encode(worst)) <= cap` (the encoder sheds data to fit any cap), and a tie-order assertion whose input is already sorted.

- **A review finding is a hypothesis until someone executes it.** Reviewers reasoning from reading produced three claims this session that measurement refuted: that a named mutation still passed the whole suite (it failed 8 pre-existing tests), that `encode` sheds its whole dedup window and raises at a near-boundary path length (it mints successfully with the window emptied), and a docstring figure that was a mid-slope sample rather than the floor. Each was relayed verbatim into the next delegation and written into the codebase before being caught. **Fix:** a claim about observable behaviour travels with its provenance ("the reviewer reasoned X — measure it before writing it down"), and any figure or failure mode destined for a comment, a doc or a lesson is measured by whoever writes it.

- **Two reviewers with different mandates catch different classes, and neither is redundant.** Spec-compliance verified that the three existing UI tabs still worked by checking their request bodies and handlers, and passed them — while a shared `showError()` was rendering "user not found" for a wiring 404 on all of them. The architect caught it. Conversely spec-compliance caught contract drift the architect passed over: response fields absent from OpenAPI's `required` list because they carried Pydantic defaults, which silently downgrades a mandatory interim flag to optional in every generated client. **Fix:** both reviews run on every task and in parallel, and a finding from one is never treated as covered by the other's verdict.

## Environment

- **A containerised server never picks up a refreshed `identities.json`, even though the capture loop keeps rewriting it on the host.** The file was bind-mounted individually, which pins the host inode; `capture_identity_addon.py` writes `identities.json.tmp` and then `os.replace()`s it, so the rename swaps in a new inode the container never sees, and mtime hot-reload can never fire. A single-file mount of a not-yet-existing `identities.json` also makes Docker create a stray *directory* on the host. **Fix:** `docker-compose.yml` mounts the whole `./mobile` directory read-only at `/app/config`, so atomic-rename refreshes stay visible and `IdentityStore`'s mtime reload keeps working.

- **Server logs "identities file not found" and falls back to synthetic/static devices (health shows `dev0`, not `id0`).** A relative `identities_path` was resolved against the process cwd instead of the config's directory when the server was launched from the repo root. **Fix:** `api/app.py` `_resolve_identities_path` resolves a relative `identities_path` against the config file's directory, so the server finds `mobile/identities.json` regardless of launch cwd.
